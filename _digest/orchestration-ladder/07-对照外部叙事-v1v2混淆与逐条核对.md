# 对照外部叙事：流传的 DeerFlow 说法逐条源码核对

> 方法论对标 DSH `_digested/orchestration-ladder/09-对照外部叙事…md`：外部叙事不是敌人，是**待核验的问题清单**。逐条给源码真相，特别标注"版本混淆"——DeerFlow v1（`main-1.x` 分支）与 v2（本仓库 `main`）是两个架构，大量流传叙事其实是 v1 的。

## 版本混淆的结构根源

v1→v2 的架构跃迁恰好是 [../graph-engineering/03-why-no-dag.md](../graph-engineering/03-why-no-dag.md) 记录的"同一条教训的两种吸收"：v1 用**显式声明式节点图**表达研究流程（planner 产计划、research_team 按步路由），v2 把图缩到**两节点 react 元图**、把全部编排动态性下放到工具层与模型。外部叙事停留在 v1 的"流程图"心智，而 v2 的心智是"harness + 涌现式委派"——这正是 ladder 专题存在的理由。

## 给读者的校验规则

读任何 DeerFlow 材料先问三句：说的是 v1 还是 v2（有没有 planner/coordinator 字样）？说的"编排"是图结构还是工具层行为？说的"持久/恢复"有没有 backend 前提（[02] 危险点 2：memory 后端默认下"持久"退化为内存）？
